## Shared component approach

**Shared core** (new `components/ChatComposer/`): the textarea with `MentionChipOverlay`, autosize, the `@` picker and its keys, paste trimming, the staged image strip, the toolbar, the send column (bell, send, Send menu), the phone fold, and toast avoidance. It knows nothing about sessions, tabs, or rooms.

**Surface adapter** (one object the surface builds and passes in):

- `value` / `setValue` and a draft key (AI: `composerInputStore` selectors so App still does not re-render per keystroke; room: local state over `draftMessage` via `useDraftPersistence`).
- `stagedImages` / `setStagedImages` (AI: tab; room: `groupChatStagedImagesById`).
- `mentionRoster` and `mentionCategory` (AI: all, excluding self; room: agents only).
- `onSubmit(intent)` where `intent` is `send | steer | hold | force`. The room adapter forwards to `window.maestro.groupChat.submitMessage` or the steer IPC and never decides send vs queue (see `src/shared/groupChatQueueModel.ts`). The AI adapter calls `processInput` with the matching options.
- `capabilities: ComposerCapabilities`, a flat object: `commandMode`, `slashCommands`, `tabCompletion`, `fileMentions`, `mentionRouting`, `saveToHistory`, `permission` (`'three-way' | 'read-only-toggle' | false`), `thinking`, `modelEffort`, `sendMenuActions` (set of intents), `imageAttach`, `voice`, `upload`. AI derives it from `useAgentCapabilities` and input mode; the room uses a constant `GROUP_CHAT_COMPOSER_CAPABILITIES`. Toolbar, sheet, keys, and Send menu read only this object, so a feature is switched off in one place.
- `aboveComposer` slot: AI renders its status chrome (row 49) there; the room renders its paused banner (row 47).

**Stays surface specific**: AI's `InputContext` completion state, slash / tab completion / command ladder hooks (mounted only when the capability is on), `useInputSync` tab bindings, `processInput`, queued cards in the transcript. Room's main-owned queue mirror, steer service, read-only flag storage, queued list placement.
